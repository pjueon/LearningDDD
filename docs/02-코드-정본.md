# 코드 정본 (저자용)

교재 본문에 나오는 클래스·메서드 시그니처의 **단일 진실 원천**. 각 장을 쓸 때 이 파일을 기준으로
쓰고, 장을 쓰다가 시그니처를 바꿔야 한다면 **먼저 이 파일을 고친 뒤** 앞장의 해당 화면도 함께
수정한다. 독자용 문서가 아니다.

체크포인트: 3장 후 / 5장 후 / 7장 후 / 9장 후.

공통 규칙
- 값 객체는 `@dataclass(frozen=True)`, 엔티티는 일반 클래스 + 명시적 `__eq__`(식별자 기준).
- 도메인 코드는 표준 라이브러리만 쓴다(`dataclasses`, `datetime`, `decimal`, `enum`, `uuid`, `typing`).
- 예외는 도메인 예외를 만든다: `DomainError` 를 루트로 3장에서 다섯 개를 정의한다 —
  `OrderCannotBeModified`(I4), `EmptyOrder`(I1), `LineNotFound`, `AlreadyShipped`(I5),
  `InsufficientStock`(할당 실패).
- **1~8장 전제(9장에서 깨짐)**: 상품 1개 = SKU 1개. 따라서 `InventoryItem.sku` 는
  `Product.id` 와 같은 값을 쓴다. 이 전제를 쓰는 화면에는 "9장에서 다시 볼 문제" 표시.
- 통화는 KRW 고정, 소수점 없음. `Decimal` 로 보관하되 원 단위 정수만 허용.
- 배송 리드타임은 **출고 다음날부터 2일**로 고정한다(도착예정일 = 출고예정일 + 2일).
  이 값은 배송 컨텍스트의 것이므로 재고/주문 코드에 상수로 박지 않고 정책 객체로 받는다.

## 체크포인트 1 — 3장 후 (Entity / VO / Aggregate)

```python
# --- 값 객체 (2장) ---
class DomainError(Exception): ...       # 모든 도메인 예외의 루트

@dataclass(frozen=True, order=True)     # order=True: 필드가 amount 하나라 금액 비교가 된다
class Money:
    amount: Decimal                     # 원 단위, 음수 허용 안 함(할인은 별도 표현)
    ZERO: ClassVar["Money"]             # 클래스 정의 후 Money.ZERO = Money.won(0)

    def __add__(self, other: "Money") -> "Money": ...
    def __sub__(self, other: "Money") -> "Money": ...   # 음수가 되면 DomainError
    def __mul__(self, count: int) -> "Money": ...       # int 만. Money * Money 는 TypeError
    def percent(self, rate: Decimal) -> "Money": ...    # 원 단위 미만 버림(ROUND_DOWN)
    def distribute(self, weights: Sequence["Money"]) -> list["Money"]: ...
    def __str__(self) -> str: ...                       # "21,000원"
    @classmethod
    def won(cls, amount: int) -> "Money": ...

# distribute: 버림으로 나눈 뒤 잔액을 앞에서부터 1원씩 배분한다. 합이 항상 보존된다.
# 반올림 정책(percent)과 배분 정책(distribute)은 여기 한 곳에만 있어야 한다.

@dataclass(frozen=True)
class Amounts:                          # 세 금액을 함께 다니게 묶은 값 객체
    subtotal: Money
    discount: Money
    shipping_fee: Money
    @property
    def total(self) -> Money: ...       # subtotal - discount + shipping_fee (I2)

@dataclass(frozen=True, order=True)
class Quantity:
    value: int                          # 1 이상 (I3). bool 은 거부한다
    def __add__(self, other: "Quantity") -> "Quantity": ...

@dataclass(frozen=True)
class Address:
    zipcode: str                        # 5자리 숫자만 허용
    road: str
    detail: str
    receiver: str
    phone: str                          # 지금은 검증하지 않는다(요구가 오면 값 객체로 분리)

@dataclass(frozen=True)
class OrderNumber:
    value: str                          # "20260907-000123" (r"\d{8}-\d{6}")
    @classmethod
    def issue(cls, today: date, seq: int) -> "OrderNumber": ...

# --- 열거형 (2장). 값 객체의 특별한 형태 ---
class SaleStatus(Enum):                 # 카탈로그 컨텍스트 (I17)
    판매중 = auto(); 판매중지 = auto()

class MemberGrade(Enum):                # 멤버가 자기 규칙을 들고 있다
    일반 = (Decimal("0"), False)
    실버 = (Decimal("0.03"), False)
    골드 = (Decimal("0.05"), True)
    def __init__(self, discount_rate: Decimal, free_shipping: bool) -> None: ...

# 할인율을 코드에 박아둔 상태. 프로모션 요구가 오면 6장 DiscountPolicy 로 옮긴다.

# --- 주문 애그리게이트 (3장) ---
class OrderStatus(Enum):
    생성됨 = auto(); 결제대기 = auto(); 결제완료 = auto()
    출고준비 = auto(); 출고됨 = auto(); 배송완료 = auto(); 취소됨 = auto()

class OrderLine:                        # 내부 엔티티. 외부에서 직접 생성하지 않는다
    line_id: UUID
    sku: str                            # 1~8장: Product.id 와 동일 (9장에서 분리)
    product_name: str                   # 주문 시점 스냅샷 (I6)
    unit_price: Money                   # 주문 시점 스냅샷 (I6)
    quantity: Quantity
    @property
    def subtotal(self) -> Money: ...

# 약속일은 라인이 아니라 주문 단위다. 분할 출고를 하지 않으므로 주문 전체가 한 날짜를 약속한다.
@dataclass(frozen=True)
class Promise:                          # 값 객체 (I22)
    ship_on: date                       # 출고 예정일 = 할당 결과의 ready_on
    arrive_by: date                     # 도착 예정일 = ship_on + 배송 리드타임
    promised_at: datetime               # 언제 약속했는지. 재조정 이력의 기준

class Order:                            # 애그리게이트 루트
    order_number: OrderNumber
    customer_id: UUID
    shipping_address: Address
    status: OrderStatus
    lines: tuple[OrderLine, ...]        # 외부에는 읽기 전용으로만 노출
    discount: Money
    shipping_fee: Money

    # 3장에서 노출하는 행위
    def add_line(self, sku: str, product_name: str,
                 unit_price: Money, quantity: Quantity) -> None: ...   # I4 검사
    def change_quantity(self, line_id: UUID, quantity: Quantity) -> None: ...
    def remove_line(self, line_id: UUID) -> None: ...                  # I1 검사
    def cancel(self) -> None: ...                                      # I5 검사
    @property
    def amounts(self) -> Amounts: ...   # 라인에서 subtotal 을 계산해 Amounts 로 묶는다
    @property
    def total_amount(self) -> Money: ...                               # I2 (= amounts.total)

    # 약속일 (3장 후반에 추가)
    promise: Promise | None             # 할당 전에는 None
    def promise_delivery(self, promise: Promise) -> None: ...          # I22. 최초 약속
    def repromise(self, promise: Promise, reason: str) -> None: ...    # 7장. 명시적 재조정

# --- 재고 애그리게이트 (3장) ---
class BatchKind(Enum):
    창고 = auto()        # 입고 완료. received_on 있음, eta 없음 (I18)
    입고예정 = auto()     # 아직 안 들어옴. eta 있음, received_on 없음 (I18)

class StockBatch:                       # 내부 엔티티
    batch_id: UUID
    kind: BatchKind
    received_on: date | None            # 창고 배치만 값이 있다
    eta: date | None                    # 입고예정 배치만 값이 있다
    expires_on: date | None
    quantity: int
    reserved: int                       # 이 배치에서 예약된 수량
    @property
    def available(self) -> int: ...     # quantity - reserved (I7, I8)

class InventoryItem:                    # 애그리게이트 루트, SKU 단위
    sku: str
    batches: tuple[StockBatch, ...]

    # 입고 흐름
    def expect(self, quantity: int, eta: date,
               expires_on: date | None) -> None: ...        # 입고예정 등록
    def arrive(self, batch_id: UUID, received_on: date) -> None: ...  # 예정 → 창고
    def delay(self, batch_id: UUID, new_eta: date) -> None: ...       # 입고 지연
    def receive(self, quantity: int, received_on: date,
                expires_on: date | None) -> None: ...        # 예정 없이 바로 입고

    # 할당
    def allocate(self, quantity: int, as_of: date) -> "Allocation": ...  # I19~I21
    def release(self, allocation: "Allocation") -> None: ...  # 취소 시 예약 해제

    @property
    def on_hand_quantity(self) -> int: ...      # 실물재고: 창고 배치의 quantity 합
    @property
    def available_quantity(self) -> int: ...    # 가용재고: 창고 배치만 (I7)
    @property
    def sellable_quantity(self) -> int: ...     # 판매가능수량 ATP: 가용 + 입고예정 잔량 (I20)

@dataclass(frozen=True)
class Allocation:                       # allocate() 의 반환값. 값 객체다
    lines: tuple["AllocationLine", ...]
    ready_on: date                      # 전량 확보되는 날 (I21). 분할 출고 안 함

@dataclass(frozen=True)
class AllocationLine:
    batch_id: UUID
    quantity: int
```

**`allocate` 는 값을 돌려준다.** 3장의 첫 판에서는 반환값이 없었지만, "입고 예정 물건도 판다"는
요구사항이 들어오면 호출자가 **언제 출고할 수 있는지** 알아야 한다. 그렇다고 주문이 `StockBatch` 를
참조하게 두면 "애그리게이트 간 참조는 ID로만" 규칙이 깨진다. 그래서 **엔티티가 아니라 값 객체
`Allocation` 을 반환**한다. 주문은 이 값에서 `ready_on` 만 꺼내 자기 안에 적어둔다.

`ready_on` 계산: 할당된 배치들의 기준일 중 가장 늦은 날. 창고 배치의 기준일은 `as_of`(오늘),
입고예정 배치의 기준일은 `eta`. 실패는 `InsufficientStock` 예외 — **ATP 기준으로도 모자랄 때만**
실패다.

## 체크포인트 2 — 5장 후 (Repository / Application Service)

```python
# --- 4장: 포트(인터페이스) ---
class OrderRepository(Protocol):
    def get(self, order_number: OrderNumber) -> Order: ...      # 없으면 OrderNotFound
    def add(self, order: Order) -> None: ...
    def next_order_number(self, today: date) -> OrderNumber: ...

class InventoryRepository(Protocol):
    def get(self, sku: str) -> InventoryItem: ...
    def get_many(self, skus: Sequence[str]) -> dict[str, InventoryItem]: ...

# 이미 있는 애그리게이트의 변경은 save() 를 부르지 않고 UoW 커밋으로 반영한다.
# (4장에서 메모리 구현으로 먼저 보여주고, 5장 UoW에서 근거를 설명)

# --- 5장: Unit of Work ---
class UnitOfWork(Protocol):
    orders: OrderRepository
    inventory: InventoryRepository
    def __enter__(self) -> "UnitOfWork": ...
    def __exit__(self, *args) -> None: ...       # 예외 시 rollback
    def commit(self) -> None: ...
    def rollback(self) -> None: ...

# --- 5장: 커맨드 / DTO ---
@dataclass(frozen=True)
class PlaceOrderCommand:
    customer_id: UUID
    items: tuple["OrderItemInput", ...]
    shipping_address: Address

@dataclass(frozen=True)
class OrderItemInput:
    sku: str
    quantity: int

@dataclass(frozen=True)
class OrderSummary:                # 표현 계층으로 나가는 읽기 전용 DTO
    order_number: str
    status: str
    total_amount: int
    line_count: int

# --- 5장: 응용 서비스 ---
class OrderingService:
    def __init__(self, uow: UnitOfWork, catalog: "CatalogPort",
                 members: "MembershipPort") -> None: ...
    def place_order(self, cmd: PlaceOrderCommand) -> OrderNumber: ...
    def cancel_order(self, order_number: OrderNumber) -> None: ...

# --- 4장: 다른 컨텍스트를 향한 포트 (10장에서 ACL로 확장) ---
class CatalogPort(Protocol):
    # 여러 항목을 한 번에 스냅샷한다. 항목마다 왕복하지 않는다.
    def snapshot(self, items: Sequence[OrderItemInput]) -> Sequence["OrderItemSnapshot"]: ...

class MembershipPort(Protocol):
    def grade_of(self, customer_id: UUID) -> "MemberGrade": ...
```

`PlaceOrderCommand` 에는 **등급을 넣지 않는다.** 등급은 클라이언트가 보내는 값이 아니라
회원 컨텍스트에 물어볼 값이다. 응용 서비스가 `members.grade_of()` 로 조회한다.

## 체크포인트 3 — 7장 후 (Domain Service / Factory / Domain Event)

```python
# --- 6장: 도메인 서비스 ---
class ShippingFeePolicy(Protocol):
    def calculate(self, lines: Sequence[OrderLine], address: Address) -> Money: ...

class DiscountPolicy(Protocol):
    def calculate(self, lines: Sequence[OrderLine], grade: "MemberGrade") -> Money: ...

# --- 6장: 팩토리. 3장의 생성자 직접 호출을 이걸로 대체한다 ---
class Order:
    @classmethod
    def place(cls, order_number: OrderNumber, customer_id: UUID,
              address: Address, items: Sequence["OrderItemSnapshot"],
              shipping_fee: Money, discount: Money) -> "Order": ...

@dataclass(frozen=True)
class OrderItemSnapshot:           # 카탈로그에서 복사해 온 값 (I6)
    sku: str
    product_name: str
    unit_price: Money
    quantity: Quantity

# --- 7장: 도메인 이벤트 ---
@dataclass(frozen=True)
class DomainEvent:
    occurred_at: datetime

@dataclass(frozen=True)
class OrderPlaced(DomainEvent):
    order_number: str
    customer_id: UUID
    items: tuple[tuple[str, int], ...]   # (sku, quantity)

@dataclass(frozen=True)
class OrderCancelled(DomainEvent):
    order_number: str
    reason: str

@dataclass(frozen=True)
class StockAllocated(DomainEvent):
    order_number: str

@dataclass(frozen=True)
class OutOfStock(DomainEvent):
    order_number: str
    sku: str

@dataclass(frozen=True)
class InboundDelayed(DomainEvent):      # 재고 컨텍스트가 발생시킨다
    sku: str
    batch_id: UUID
    old_eta: date
    new_eta: date

@dataclass(frozen=True)
class PromisedDateChanged(DomainEvent): # 주문이 발생시킨다. 고객 통지로 이어진다
    order_number: str
    old_ship_on: date
    new_ship_on: date
    reason: str

# 애그리게이트는 이벤트를 모아만 둔다. 발행은 응용 계층(UoW 커밋 후).
class Order:
    events: list[DomainEvent]            # 7장에서 추가되는 필드
    def pull_events(self) -> list[DomainEvent]: ...

class MessageBus:
    def subscribe(self, event_type: type[DomainEvent],
                  handler: Callable[[DomainEvent], None]) -> None: ...
    def publish(self, events: Sequence[DomainEvent]) -> None: ...

# --- 7장 시점의 응용 서비스 완성형. 1장 화면 11의 미리보기가 이 코드다 ---
class OrderingService:
    def __init__(self, uow: UnitOfWork, catalog: CatalogPort,
                 members: MembershipPort, fee_policy: ShippingFeePolicy,
                 discount_policy: DiscountPolicy, bus: MessageBus) -> None: ...

    def place_order(self, cmd: PlaceOrderCommand) -> OrderNumber:
        # 1) 스냅샷/등급 조회  2) Order.place()  3) add + commit  4) 이벤트 발행
        ...
```

7장에서 `place_order` 는 커밋 후 `bus.publish(order.pull_events())` 를 호출하는 형태로 바뀐다.
**5장 코드가 7장에서 어떻게 바뀌는지 diff를 화면으로 보여준다.**

## 체크포인트 4 — 9장 후 (Bounded Context 분리)

`Product` 가 세 개로 쪼개지고, 모듈 구조가 컨텍스트별로 재편된다.

```python
# catalog/  — 무엇을 파는가
class Product:                     # 애그리게이트 루트
    product_id: UUID
    name: str
    price: Money                   # I16
    status: SaleStatus             # 판매중 / 판매중지 (I17)
    composition: tuple["ProductSku", ...]   # 상품 1개가 여러 SKU로 구성될 수 있다

@dataclass(frozen=True)
class ProductSku:
    sku: str
    quantity_per_product: int      # 3개 묶음 세트면 3

# inventory/  — 몇 개 팔 수 있는가
class Sku:                         # 재고 컨텍스트가 아는 "품목". 판매가를 모른다
    sku: str
    name: str                      # 재고 담당자가 쓰는 이름(카탈로그 상품명과 다를 수 있다)
    manages_expiry: bool
class InventoryItem: ...           # 체크포인트 1과 동일

# warehouse/  — 어느 랙에 있는가
class StoredItem:
    sku: str
    location: "Location"
    quantity: int

# ordering/  — 카탈로그를 직접 참조하지 않는다.
# CatalogPort 시그니처는 체크포인트 2와 같다. 달라지는 것은 구현이다:
# 9장 이후의 구현은 Product.composition 을 펼쳐 SKU 라인들로 변환한다.
```

`OrderLine.sku` 는 9장 이후에도 `sku` 문자열을 그대로 쓴다(주문은 SKU 단위로 기록).
바뀌는 것은 **"그 sku를 어디서 얻는가"** — 이전에는 `Product.id`, 이후에는
`CatalogPort.snapshot()` 이 상품 구성을 펼쳐 SKU 라인들로 변환해 준다.

## 시그니처 변경 이력

시그니처를 바꿀 때 여기에 한 줄 남긴다. 이미 쓴 장을 함께 고쳤는지 체크.

| 변경 | 영향받는 장 | 반영 완료 |
|---|---|---|
| `CatalogPort.snapshot` 을 항목 단위 → 목록 단위로 (`Sequence[OrderItemInput]`) | 1장 화면 11 | O |
| 회원 등급 조회를 `PlaceOrderCommand.grade` 가 아니라 `MembershipPort.grade_of()` 로 | 1장 화면 11 | O |
| 7장 시점 `OrderingService.__init__` 인자 6개 확정 | 1장 화면 11 | O |
| `Money` 에 `percent()`·`distribute()`·`__str__` 추가, `order=True` | 2장 | O |
| `Amounts` 값 객체 신설(I2 가 여기 산다). 3장에서 `Order` 안으로 옮길 후보 | 2장 | O |
| `SaleStatus`·`MemberGrade` 신설. `MemberGrade` 는 멤버가 규칙을 보유 | 2장 | O |
| `Quantity` 에 `order=True`·`__add__`, bool 거부 | 2장 | O |
