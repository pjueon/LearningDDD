# 집필 절차 (저자용)

새 장을 쓸 때 이 문서만 보고 시작할 수 있어야 한다. 독자용 문서가 아니다.

읽는 순서: `00-기획.md`(무엇을 왜) → `01-커리큘럼.md`(그 장에 무엇이 들어가는지) →
`02-코드-정본.md`(그 시점의 클래스/메서드 시그니처) → 이 문서(어떻게 쓰고 어떻게 검증하는지).

## 1. 새 장 집필 절차

1. **커리큘럼에서 그 장의 항목·페이지 수·시간을 확인한다.** 페이지 수는 지키는 것이 좋다.
   바꿔야 하면 `01-커리큘럼.md` 의 장별 표기와 §3 합계표를 **함께** 고치고 검산한다(§4 참고).
2. **정본에서 그 시점의 시그니처를 확인한다.** 정본과 다른 코드를 쓰려면
   **정본을 먼저 고치고** 변경 이력 표에 한 줄 남긴다. 이미 쓴 장에 영향이 있으면 그 장도 고친다.
3. **앞 장들이 그 장에 남긴 약속을 찾는다.** `grep -o '"later">[^<]*' docs/ch*.html` 로
   "N장에서 다시 볼 문제" 표시를 전부 뽑아, 이번 장이 갚아야 할 빚을 확인한다.
   갚지 않으면 독자가 배신감을 느낀다.
4. `docs/chNN.html` 을 쓴다. 골격은 `ch02.html` 을 복사해서 쓰는 게 빠르다.
5. **`book.js` 의 `BOOK` 배열에서 그 장에 `ready: true` 를 켠다.** 안 켜면 목차에서 회색이고
   링크도 안 걸린다.
6. **앞 장 마지막 페이지의 `.chapter-end` 링크를 이번 장으로 바꾼다.**
7. **새로 등장한 업무 용어를 `book.js` 의 `TERMS` 에 추가**하고 본문에서
   `<span class="term" data-term="...">` 로 연결한다.
8. §3 검증을 돌린다. §4 검산을 돌린다.
9. 커밋한다. 멀티라인 한글 메시지는 scratchpad 에 파일로 쓰고 `git commit -F <파일>`.

## 2. 마크업 규약

장 파일의 골격. `data-chapter` 는 `BOOK` 의 `id` 와 같아야 한다.

```html
<html lang="ko" data-chapter="ch03">
...
<main id="book"><div class="inner">

<!-- ─────────────────────────────────────────── 페이지 1 -->
<section class="screen" data-title="사이드바에 보일 짧은 제목">
  <p class="kicker">3장 · 페이지 1</p>
  <h1>...</h1>   <!-- 첫 페이지만 h1, 나머지는 h2 -->
</section>

</div></main>
<script src="assets/book.js"></script>
```

| 컴포넌트 | 마크업 | 쓰는 자리 |
|---|---|---|
| 도입 문단 | `<p class="lead">` | 페이지 1의 첫 문단 |
| 강조 상자 | `<div class="box note\|warn\|good\|bad">` + `<p class="box-t">제목</p>` | note=설명, warn=주의, good=개선 결과, bad=문제 상황 |
| 접힌 상자 | `<details class="fold"><summary>제목</summary><div class="fold-body">…</div></details>` | "더 깊이", 판단 훈련의 답 |
| 모범답안 | `<details class="fold answer">` | 과제 답. 초록색 summary |
| 코드 | `<pre><span class="cap"># 파일명 또는 범위</span><code>…</code></pre>` | `cap` 은 `code` 밖에 둘 것(하이라이팅 대상 제외) |
| 코드 강조 | `<b class="hl">…</b>` (code 안에서) | 추가/변경된 줄 |
| 코드 해설 | 코드 안에 `# 1`, `# 2` 마커 + `<ol class="notes"><li><span class="ln">47행</span>…` | 20줄 넘는 코드에는 필수 |
| Before/After | `<div class="tabs"><div class="tab" data-label="…">…</div>…</div>` | 탭바는 JS가 생성 |
| 표 | `<div class="table-wrap"><table>…` | wrap 없으면 좁은 화면에서 넘친다 |
| 대화 | `<div class="dialog"><div class="line"><div class="who">은수</div><div class="say"><p>…</p></div></div>` | 요구사항 전달, 팀 간 충돌 |
| 다이어그램 | `<figure class="fig"><svg viewBox="0 0 700 180" role="img" aria-label="…">` + `figcaption` | 색은 클래스로: `svg-fg`, `svg-muted`, `svg-line` |
| 용어 툴팁 | `<span class="term" data-term="sku">SKU</span>` | 정의는 `book.js` 의 `TERMS` 에만 둔다 |
| 뒤로 미루기 | `<span class="later">9장에서 다시 볼 문제</span>` | 의도적으로 미룬 것. **반드시 그 장에서 갚는다** |
| 요약 | `<div class="summary"><h3>핵심 요약</h3><ol>…` | 마지막 페이지 |
| 과제 | `<div class="task"><h3>직접 해보기</h3>` | 마지막 페이지. 바로 아래에 모범답안 |
| 퀴즈 | `<div class="quiz" data-answer="2">` + `<p class="q">` + `<ol class="options"><li data-why="…">` + `<div class="explain">` | 마지막 페이지. 장당 3개 |

**HTML 이스케이프**: `<code>` 안의 `<`·`>`·`&` 는 `&lt;`·`&gt;`·`&amp;` 로 쓴다.
`->` 는 `-&gt;`, `if x < 3` 은 `if x &lt; 3`. 하이라이터는 텍스트 노드를 다시 이스케이프하므로
이중 이스케이프되지 않는다.

**퀴즈 작성 규칙**
- `data-answer` 는 1부터 시작하는 정답 번호.
- 오답 선택지의 `data-why` 는 "왜 틀렸는지"를 적는다. **틀린 이유가 그럴듯해야** 훈련이 된다.
- `.explain` 에는 본문에 없는 내용을 넣는다. 정답 확인만 하는 해설은 가치가 없다.

## 2-1. 다른 페이지를 인용할 때

`book.js` 가 본문 텍스트에서 다음을 자동으로 처리한다(마크업 불필요, `<code>`·`<pre>`·링크·kicker·그림 안은 건드리지 않는다).

- **"페이지 N"**(같은 장) → 링크. 누르거나 마우스를 올리면 그 페이지를 복제해 미리보기 팝업으로 보이고, '이 페이지로 이동' 뒤에는 돌아가기 버튼이 뜬다. "페이지 4·6", "페이지 2~3" 처럼 이어 쓴 번호도 각각 링크가 된다.
- **"N장 페이지 M"** → `chNN.html#sM` 링크. 다른 장은 미리보기가 안 된다(`file://` 에서 다른 파일을 읽을 수 없다). 이동한 쪽에 돌아가기 버튼이 뜬다.
- **I1~I22** → `RULES` 사전의 한 줄 뜻(불변식)을 툴팁으로. 불변식의 뜻이 바뀌면 `RULES` 를 고친다. 처음 정의되는 장(`RULE_INTRO`, 기본 3장)보다 앞 장에서는 뜻 대신 안내 문구가 나온다. 번호를 다른 뜻으로 쓰는 자리는 `<code>` 로 감싸면 건너뛴다.

그래서 집필할 때는:

1. **"N장 페이지 M" 은 한 줄에 붙여 쓴다.** "N장" 과 "페이지 M" 사이에서 줄을 바꾸면 인식이 안 되어, 같은 장의 "페이지 M" 으로 잘못 링크된다.
2. **다른 장의 페이지는 반드시 "N장 페이지 M"** 으로 쓴다. 장 이름 없는 "페이지 N" 은 항상 같은 장으로 읽힌다.
3. **"페이지 4·14장 페이지 3" 처럼 번호 뒤에 `·` `,` `~` 와 숫자가 오면** 번호 범위로 읽힌다. "과"·"와" 등으로 끊는다.
4. 링크가 가리키는 페이지에 **인용한 표·수치가 실제로 있는지** 본다. 자동 링크가 되었다고 번호가 맞는 것은 아니다. 페이지 수보다 큰 번호는 probe 가 잡지 못하므로 장 전체를 한 번 훑는다.
5. **본문 논증이 그 표·그림을 보면서 따라가야 하면** 그 자리에 작게 다시 보인다(`<div class="box note"><p class="box-t">다시 보기: …</p>`). 대상이 접힌 상자 안에 있으면 미리보기에서도 접혀 보이므로 한 줄 요약을 붙인다.
6. **다른 장의 내용**을 근거로 쓸 때는 괄호 한 줄 요약을 붙이거나 다시 보인다.
7. **퀴즈·직접 해보기가 앞 페이지의 표·코드를 전제하면** 그 표를 문제 옆에 다시 보인다. 정답이 드러나는 재게시는 하지 않는다.

### 3.2 새 장 점검 — 임시 probe

장 파일 사본에 스크립트를 붙여 **모든 페이지를 켜고** 검사한다. 확인할 것:
코드 블록 가로 넘침(1280px 기준 0이어야 함), 페이지 수, 용어 툴팁의 미연결 개수
(`.term:not([data-def])` 가 0이어야 함 — `TERMS` 에 없는 `data-term` 을 쓴 것).

```javascript
// chNN.html 사본의 </body> 앞에 붙인다
window.addEventListener('load', function () {
  var res = [], scs = document.querySelectorAll('.screen');
  for (var i = 0; i < scs.length; i++) {
    scs[i].classList.add('is-active');
    var pres = scs[i].querySelectorAll('pre');
    for (var j = 0; j < pres.length; j++) {
      var over = pres[j].scrollWidth - pres[j].clientWidth;
      if (over > 1) res.push('s' + (i+1) + 'pre' + (j+1) + '=' + over);
    }
    scs[i].classList.remove('is-active');
  }
  var box = document.createElement('pre'); box.id = 'probe-out';
  box.textContent = (res.length ? 'OVERFLOW ' + res.join(',') : 'NO-OVERFLOW')
    + ' screens=' + scs.length
    + ' termsMissing=' + document.querySelectorAll('.term:not([data-def])').length;
  document.body.appendChild(box);
});
```

가로 넘침이 나오면 **코드 줄을 줄인다**(문자열을 나눠 이어붙이기).
본문 폭은 45rem, 코드 폰트는 .82rem 이라 약 90자까지 들어간다.
레이아웃을 넓히는 방향으로 대응하지 않는다.

probe 의 `NO-OVERFLOW` 는 `<pre>` 만 본다. **페이지 자체의 가로 스크롤**은 따로 본다 —
페이지마다 `is-active` 를 돌리면서 그 페이지의 `.term[data-def]` 마다 `mouseover` 를 보내고
`document.documentElement.scrollWidth > clientWidth` 인지 확인한다. 본문에 넣은 표·그림이
넓어도 여기서 잡힌다. (툴팁은 `book.js` 가 body 에 붙인 `#tip` 하나를 화면 안에 맞춰 띄운다.
예전 `.term::after` 방식은 줄 끝에서 페이지 가로 스크롤을 만들었다.)

### 3.4 코드 해설의 행번호 대조 — **가장 자주 틀리는 것**

`ol.notes` 의 `<span class="ln">47행</span>` 은 반드시 실제 코드와 대조한다.
1장 집필 때 26개 중 대부분이 1~2행씩 어긋나 있었다. 빈 줄 세는 것을 사람이 못 한다.

```python
# 그 파일의 <pre> 코드 블록마다 줄번호를 붙여 파일로 뽑는다.
# (콘솔이 cp949 라 한글이 깨지므로 파일로 쓴 뒤 읽는다)
import io, re
s = io.open('docs/ch03.html', encoding='utf-8').read()
out = []
for n, m in enumerate(re.finditer(r'<pre>.*?<code>(.*?)</code>\s*</pre>', s, re.S), 1):
    out.append('===== 코드 블록 %d =====' % n)
    for i, l in enumerate(m.group(1).rstrip('\n').split('\n'), 1):
        plain = re.sub(r'<[^>]+>', '', l).replace('&lt;', '<').replace('&gt;', '>')
        out.append('%3d| %s' % (i, plain))
io.open('lines.txt', 'w', encoding='utf-8').write('\n'.join(out))
```

`<code>` 만으로 찾으면 본문의 인라인 코드까지 잡힌다(2장은 259개 대 34개).
`<pre>` 안으로 한정할 것.

## 4. 검산

### 4.1 커리큘럼 합계

장별 `**페이지 N · M시간**` 표기의 합과 §3 구간 합계표가 일치해야 한다.

```python
import io, re
s = io.open('authoring/01-커리큘럼.md', encoding='utf-8').read()
rows = re.findall(r'^\| (?!구간|\*\*합계)[^|]+\| [^|]+\| (\d+) \| ([\d.]+)h \|$', s, re.M)
per  = re.findall(r'\*\*페이지 (\d+) · ([\d.]+)시간\*\*', s)
print('구간', sum(int(a) for a, b in rows), sum(float(b) for a, b in rows))
print('장별', sum(int(a) for a, b in per),  sum(float(b) for a, b in per), len(per))
```

바뀌면 함께 고칠 곳: `01-커리큘럼.md` 의 장별 표기·§3 표·§4 트랙 주차,
`00-기획.md` §6 분량 목표, `index.html` 의 분량 문구와 트랙 카드,
`book.js` 의 `BOOK` 항목(`screens`, `hours`).

### 4.2 불변식 커버리지

기획서의 I1~I22 가 교재에 최소 한 번 등장해야 한다. 전체 집필 후 확인.

```bash
for i in $(seq 1 22); do

```

### 4.3 미룬 약속

```bash
grep -o '"later">[^<]*' docs/ch*.html
```
"N장에서 다시 볼 문제" 가 실제로 그 장에서 갚아졌는지 확인한다.
`.later` 배지는 **코드 옆에서 미룬 것**에만 쓴다. 산문에서 "6장에서 다룹니다"라고 쓴 약속은
이 grep 에 안 걸리므로, 그 장을 쓸 때 앞 장을 `grep -n "N장" docs/ch*.html` 로 훑는다.

## 5. 자주 하는 실수

1. **행번호 어긋남** — §3.4. 반드시 스크립트로 대조한다.
2. **페이지 삽입 위치 오류** — 페이지를 중간에 끼워 넣으면 `kicker`·주석 번호를 다시 매겨야 하고,
   본문의 "페이지 N" 상호 참조도 전부 갱신해야 한다.
   `grep -n "페이지 [0-9]" docs/chNN.html | grep -v kicker` 로 확인한다.
3. **정본과 본문의 시그니처 불일치** — 1장 페이지 16에서 실제로 발생했다.
   본문 코드를 쓸 때 정본을 열어놓고 쓴다.
4. **`TERMS` 에 없는 `data-term`** — 툴팁이 조용히 안 나온다. §3.2 로 잡는다.
5. **`ready: true` 를 안 켜서** 목차에서 새 장이 회색으로 남는 것.
6. **`.later` 표시만 하고 안 갚는 것** — §4.3.
7. **페이지 참조 줄바꿈·범위 오인** — §2-1. `grep -n "[0-9]장$" docs/chNN.html` 로 줄 끝의 "N장" 을 확인한다.
